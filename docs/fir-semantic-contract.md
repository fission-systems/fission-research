# FIR 독립 중간 의미론 계약

설계 결정: 2026-10-03. 독립 의미론의 요구사항이며, 아래 전체 계약의 구현 완료를 뜻하지 않는다.

## 의미의 소유자

FIR은 Fission이 정의하고 버전 관리하는 중간 의미론이다. FSL은 아키텍처의 인코딩과 의미를 기술하고, 컴파일러는 그 의미를 FIR의 타입·연산·상태·효과 규칙으로 검증한다. 분석, 최적화, 실행, 재컴파일은 이 계약을 기준으로 한다.

```text
직접 작성한 FSL ────────────┐
공식 ISA / VM 자료 → FSL ───┼→ 검증된 단일 FIR
SLEIGH / SLA → 이관 어댑터 ─┘       ├→ 분석 / 그래프 / 근거 패킷
                                    ├→ C / Rust 출력
                                    └→ 실행 / 재컴파일 backend
```

SLEIGH/SLA/P-code의 opcode 번호, varnode 표현, template 지시문은 입력 형식의 사실이다. FIR의 연산 식별자나 의미 정의를 결정하지 않는다. 이관 어댑터는 원본 의미를 FIR 계약에 대응시키고 출처와 지원 범위를 남긴다. 직접 작성한 FSL은 이 어댑터를 거치지 않는다.

초기 Notion 연구에서 제안된 `Rich FIR → P-code+ → 기존 소비자`는 과거 호환 구상으로 남긴다. 현재 목표 아키텍처의 필수 경로는 FIR을 직접 소비한다. 기존 소비자 연결이 필요하면 P-code 출력은 별도 projection이며, 그 표현 한계가 FIR의 표현 한계를 정하지 않는다. NIR/HIR처럼 의미 소유자를 나누지 않는다.

## 각 연산이 정의해야 할 것

| 항목 | FIR 계약 |
|---|---|
| 값과 타입 | 비트 폭, 정수 해석, 부동소수점 형식, uniform/lane/mask 도메인, 주소 공간·객체 참조의 구분 |
| 순수 계산 | 입력·결과 타입, 정확한 비트 결과, overflow·rounding·NaN·shift 경계 규칙 |
| 상태 | 레지스터 byte view와 alias, 플래그, VM stack, 메모리 도메인, lane 상태의 식별과 범위 |
| 효과 | 읽기·쓰기 순서, 관찰 가능한 효과, atomic ordering·scope, 동기화 조건 |
| 제어 흐름 | 후속 block, 호출·반환, 예외·trap, 명령/프로그램 위치와의 대응 |
| 정의 범위 | 전제, ISA에서 허용한 비결정성·미정의 동작, 구현 의존성, 미지원 의미 |
| 변환 조건 | 연산 제거·재배치·병합이 허용되는 전제와 보존해야 할 관찰 |
| 근거 | 아키텍처·버전 범위, 출처, 변환 기록, 실제 검증 범위 |

연산 이름만 같다는 이유로 의미를 합치지 않는다. 같은 덧셈도 wrapping 결과, carry 출력, trap 발생 여부가 다를 수 있다. 공통 연산을 사용하되 이러한 차이를 연산 계약과 명시적 효과로 표현한다.

GPU의 lane mask·barrier와 VM의 operand stack·객체·예외는 FIR 안에서 정의할 도메인이다. 불투명한 vendor opcode 호출을 최종 의미 정의로 삼지 않는다. 새 도메인 연산은 타입 규칙, 상태 전이, 관찰 효과와 backend 지원 계약을 추가해야 한다. 연산을 표현하는 능력과 특정 backend에서 실행하는 능력은 별도로 선언한다.

## 실행 의미

FIR 프로그램 `P`의 의미는 입력 상태 `S`에서 허용되는 결과와 관찰 trace의 관계로 정의한다. 결정적인 연산은 결과가 하나이며, 아키텍처가 허용하는 비결정성은 가능한 결과 집합과 제약을 기록한다.

```text
meaning(P, S) = {(outcome, S', observable_trace)}
outcome       = 정상 종료 | trap | 예외 | 그 밖의 명시된 실행 결과
```

상태에는 프로그램이 접근하는 도메인과 외부 환경의 전제가 포함된다. 단일 명령의 최종 레지스터 값만으로 메모리·동기화·예외를 포함한 프로그램 동치를 판정하지 않는다.

`unsupported`는 게스트 프로그램의 trap이 아니다. FIR 모델 또는 backend가 결과를 계산할 수 없다는 상태다. 실행기 입력 검증 실패도 게스트 ISA의 fault와 구분한다. 현재 reference 실행기의 실패 전 상태 보존 정책을 모든 ISA의 fault 전 쓰기 정책으로 일반화하지 않는다. 실제 fault 전 효과는 해당 연산의 계약에 따라 표현해야 한다.

재컴파일은 지원 범위와 환경 전제 아래에서 원본과 대상의 관찰 가능한 의미 관계를 보존해야 한다. 상태 대응에는 레지스터/메모리/VM 표현의 mapping이 필요하다. 차등 실행은 이 계약의 관찰 증거이며 전체 동치 증명으로 승격하지 않는다.

## 현재 구현과의 연결

현재 Rust `fission-fsl`에는 `FirOp`, 타입·SSA 검증과 자체 reference 실행 경로가 있다. wrapping 덧셈, carry, 레지스터·플래그, VM stack, masked lane 상태를 제한된 slice에서 사용한다. 각 slice의 실제 범위는 [진행 현황](research-status.md)에 기록한다.

직접 SLA 이관의 `INT_ADD`는 기존 FIR wrapping 덧셈으로 대응된다. SLA의 `BUILD`는 피연산자 의미를 해석하는 이관 지시문으로 소비된다. 출력 FIR의 실행 연산으로 남기지 않는다. 이 첫 slice는 [이관 기록](../experiments/migration/sla-first-slice/README.md)을 따른다.

이것은 독립 FIR의 시작이며, 위 표의 전체 타입·제어 흐름·메모리·예외·동기화 의미론을 구현한 상태는 아니다. provenance는 출처 추적 근거이고, 실행 의미의 정확성을 대신하지 않는다.

## 다음 구현 단위

1. 현재 연산별로 타입 규칙·비트 결과·상태 효과·실패 범위를 문서화하고 compiler/reference/C/Rust 경로와 연결한다.
2. 즉시값, 확장·절단, 비교·조건 분기의 자체 FIR 계약을 정의한다. SLA opcode mapping은 이 계약을 소비하는 어댑터로 확장한다.
3. 여러 명령의 block과 상태 전달을 같은 FIR 안에 추가하고, read/write alias·효과 순서·trap 경계 반례를 검증한다.
4. 메모리, GPU 동기화, VM 객체·예외를 추가할 때 도메인별 전제와 관찰 trace를 명시한다. 지원하지 않는 backend는 정확한 거부를 반환한다.

이 순서는 의미론 기반을 구현으로 확인하기 위한 계획이다. 최적화·출력·JIT/AOT가 규칙을 독자적으로 추측하지 않도록 같은 계약에 연결한다.
