# AMDGPU GFX900 static probe

This is the first GPU artifact in the research corpus. It contains a locally authored GFX9 assembly fragment and a minimal LLVM IR kernel compiled by LLVM. The assembly fragment is for encoding and ELF inspection; it is not a launchable kernel. The IR object is a valid AMDGPU relocatable code object, but has not been loaded or executed on a GPU.

## Reproduction

```sh
llvm-mc -triple=amdgcn-amd-amdhsa -mcpu=gfx900 -show-encoding experiments/gpu/amdgpu-gfx900/probe.s
llvm-mc -triple=amdgcn-amd-amdhsa -mcpu=gfx900 -filetype=obj -o experiments/gpu/amdgpu-gfx900/probe.o experiments/gpu/amdgpu-gfx900/probe.s
llvm-objdump -d --mcpu=gfx900 experiments/gpu/amdgpu-gfx900/probe.o
llvm-readobj --file-headers --sections --symbols --notes experiments/gpu/amdgpu-gfx900/probe.o
llc -mtriple=amdgcn-amd-amdhsa -mcpu=gfx900 -filetype=obj -o experiments/gpu/amdgpu-gfx900/add_kernel.o experiments/gpu/amdgpu-gfx900/add_kernel.ll
llvm-objdump -d --mcpu=gfx900 experiments/gpu/amdgpu-gfx900/add_kernel.o
llvm-readobj --file-headers --sections --symbols --notes experiments/gpu/amdgpu-gfx900/add_kernel.o
python3 tools/gpu_elf_probe.py experiments/gpu/amdgpu-gfx900/add_kernel.o > experiments/gpu/amdgpu-gfx900/add_kernel.elf.json
```

Recorded environment: Homebrew LLVM 22.1.8 on macOS arm64, target `amdgcn-amd-amdhsa--gfx900`.

The initial encoding probe reported:

| Instruction | Bytes |
|---|---|
| `s_mov_b32 s0, 1` | `81 00 80 be` |
| `v_add_u32_e32 v0, v1, v2` | `01 05 00 68` |
| `s_barrier` | `00 00 8a bf` |
| `s_endpgm` | `00 00 81 bf` |

The `add_kernel.ll` object is `elf64-amdgpu`, `ET_REL`, with `EM_AMDGPU`, HSA OSABI, ABI version 4, and `EF_AMDGPU_MACH_AMDGCN_GFX900`. LLVM emits an AMDGPU metadata note and an `add.kd` kernel descriptor. The note reports a 272-byte kernarg segment; visible arguments occupy offsets 0, 8, and 12, followed by hidden launch arguments. It also reports wavefront size 64, 14 SGPRs, and 2 VGPRs.

These values come from LLVM 22.1.8's object writer and metadata emitter. They are useful reference output for an independent parser, but they are not independent proof of kernel ABI or instruction semantics. The IR stores one scalar result to the same output address from every work item, so this probe must not be treated as a race-free workload. The sample is intentionally not executed.

`probe.elf.json` and `add_kernel.elf.json` are generated by the independent probe. The `add_kernel` JSON preserves the MessagePack-decoded note tree and input hash. The corresponding LLVM reference views are in `probe.encoding.txt`, `add_kernel.disasm.txt`, and `add_kernel.readobj.txt`.

The first GFX900 FSL compiler/decoder slice is described in [`docs/fsl-first-compiler-slice.md`](../../../docs/fsl-first-compiler-slice.md). [`specs/gpu/amdgcn/gfx900-first.fsl`](../../../specs/gpu/amdgcn/gfx900-first.fsl) compiles into the pattern package at `data/patterns/amdgpu-gfx900.json`. `probe.text.bin` is the extracted `.text` section from `probe.o`; [`probe.decode.json`](probe.decode.json) records the decoded instructions, package hash, and source FSL hash. The decoder recognizes only the four instructions in this fixture and does not imply execution or complete ISA support.

Recreate the text section and decoder record with:

```sh
llvm-objcopy --only-section=.text -O binary experiments/gpu/amdgpu-gfx900/probe.o experiments/gpu/amdgpu-gfx900/probe.text.bin
python3 tools/fslc_probe.py specs/gpu/amdgcn/gfx900-first.fsl --output data/patterns/amdgpu-gfx900.json
python3 tools/fsl_decode_probe.py experiments/gpu/amdgpu-gfx900/probe.text.bin --patterns data/patterns/amdgpu-gfx900.json --output experiments/gpu/amdgpu-gfx900/probe.decode.json
```

## AQL dispatch packet fixture

`dispatch_packet.sample.bin` is a hand-authored, little-endian, 64-byte HSA kernel-dispatch packet fixture. Its grid and workgroup are `[64, 1, 1]`; the kernel object and kernarg address are synthetic values, the system-scope acquire/release flags are set, and no completion signal is attached. It is not a packet captured from a running GPU, and its handle is intentionally unrelated to `add_kernel.o`. [`kernel-object-link.json`](kernel-object-link.json) records the source-traced ROCclr/ROCr path that maps a loaded symbol to the dispatch field while keeping the runtime address unobserved.

Decode it with:

```sh
python3 tools/aql_dispatch_probe.py experiments/gpu/amdgpu-gfx900/dispatch_packet.sample.bin > experiments/gpu/amdgpu-gfx900/dispatch_packet.sample.json
```

The probe keeps the exact 64 bytes, offsets, decoded header/setup bits, launch geometry, segment sizes, opaque handles, and reserved fields. It accepts a raw packet capture with `--offset` and `--count`; the default kernarg pointer layout is the 64-bit HSA large model, and `--pointer-model=32` selects the small-model layout.
